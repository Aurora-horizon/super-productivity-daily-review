# 每日复盘与计划 v2.9.2

适用于 Super Productivity 19.1.0 的本地插件。它通过官方 Plugin API 读取任务，并把每日计划快照、完成状态和未完成原因保存在插件同步数据中。

## 安装

1. 打开 Super Productivity。
2. 进入“设置 → 插件 / Plugins”。
3. 导入 `daily-review-plugin-v2.9.2.zip`。
4. 启用“每日复盘与计划”。
5. 从顶部按钮、菜单或命令面板打开。

## v2.9.2 界面

- **每日**：动态完成率环形图、具体时间任务时间线、按状态分组的全天任务、任务详情滑入抽屉、筛选器和原因记录。
- **双向勾选**：可在插件中直接勾选或取消任务完成状态，修改会同步回 Super Productivity；时间线、全天任务、其他完成和详情抽屉均支持操作。
- **逾期队列**：今天的页面会汇总之前所有未完成任务；一次性任务逾期 2 天后不再提供机械顺延，改为人工重新安排。
- **显式任务类型**：在任务详情中直接选择“每日任务 / 一次性任务 / 短期任务 / 长期任务”，短期和长期任务可填写持续天数。
- **类型独立保存**：任务类型使用独立存储键，不会被后台任务快照覆盖，刷新或重新打开后仍会保留。
- **任务系列**：每日、短期、长期任务保存后会按未来 7 天自动补齐，每个日期只生成一次，支持暂停系列。
- **历史类型同步**：设置任务类型后，会按“项目 + 去除日期前缀后的标题”同步到同系列的历史和未来实例。
- **系列标题清理**：自动生成的新任务会去掉标题开头的 `10-28`、`10月28号`、`2026年10月28日` 等日期前缀。
- **旧副本修复**：升级后会自动检查并修正之前已经生成、但仍带日期标题的系列任务；历史原始任务标题保持不变。
- **逾期仅限一次性任务**：每日、长期、短期和重复任务不会进入逾期延期队列，过期后按当天错过处理。
- **无法完成**：一次性任务可以记录“无法完成”原因，不会计为完成，也不会继续留在逾期队列。
- **原生重复优先**：已使用 Super Productivity 原生重复机制的任务不会重复生成副本。
- **重复任务保护**：自动识别 Super Productivity 重复任务；每日任务超过两天未完成会按当天错过处理，不会搬到明天叠加。
- **改期撤销**：每次移至今天或顺延都会记录原日期，顶部“撤销改期”和移动后的提示均可回退。
- **未来任务回退**：未来日期会正确显示全天任务，并可直接“移到今天”。
- **每日收尾**：点击“结束今天”逐项选择顺延、补勾完成或保持未完成；每日任务改为“记为错过”，可记录原因并保存日结时完成率。
- **完成分类**：区分补完历史、提前完成和临时额外完成，避免把不同性质的成果混在一起。
- **原因口径**：今天尚未完成的任务不会再提示“原因待补”，只有已经过去且仍未完成的任务才需要补充原因。

## 任务类型判定

- 优先使用任务详情中的显式类型设置。
- 原生重复任务依据 `repeatCfgId` 自动识别，不会生成插件副本。
- 每日、短期、长期任务保存后自动补齐未来 7 天；滚动打开插件会继续补齐。
- 短期、长期任务按填写天数保存结束日期，超过结束日期后停止生成。
- 每日、短期、长期和重复任务不进入逾期延期队列，过期后自动按当天错过处理。
- 同系列任务通过“项目 + 去除日期前缀的标题”匹配，因此 `10-28 晨间阅读` 与 `10-29 晨间阅读` 会归为同一系列。
- 只有一次性任务可以进入逾期列表并选择移到今天、重新安排、顺延或无法完成。
- “无法完成”会记录原因，不计入完成，并从当前计划中移除；原计划日保留为未完成记录。
- 一次性任务逾期超过 2 天后需要人工重新安排，不再一键滚到明天。
- **归档任务**：受 Super Productivity 官方 Plugin API 限制，已归档任务会显示但勾选框禁用；未归档任务均可双向切换。
- **完成日历**：标准月历。每天显示完成率、状态和任务点；悬停显示摘要，点击带过渡进入当天明细。
- **趋势**：30 天完成率折线图，带绘制动画、悬停数据提示、80% 目标线、近 7 天变化和原因分布。
- **计划导入**：保留手动 JSON 兜底，同时提供 Trae 自动写入指令。
- **实时同步**：在 Super Productivity 或插件内创建、完成、取消完成、修改、删除任务后，双方状态会自动刷新。
- **日期口径**：遵循 Super Productivity 的“一天的开始时间”设置，而不是固定按午夜计算。
- **历史校准**：已删除任务不会继续留在当前/未来统计中；历史中的已删除孤立任务也会清理。

## 自动写入（推荐）

Super Productivity 19.1.0 自带本地 REST API：

- 地址：`http://127.0.0.1:3876`
- 打开方式：设置 → 杂项 → 启用本地 REST API
- 访问令牌：同一设置区域复制
- 只监听本机，不应把端口暴露到公网

配套脚本：`sp-plan.ps1`

```powershell
powershell -ExecutionPolicy Bypass -File "sp-plan.ps1" -PlanFile ".\plan.json"
```

脚本会：

1. 从本机令牌文件或 `SP_REST_TOKEN` 读取令牌。
2. 解析项目与标签。
3. 用任务备注中的 `sp-plan:<id>` 标记识别重复任务。
4. 新建或更新任务，避免重复创建。
5. 输出新建、更新、跳过、失败数量。

## 计划 JSON

```json
{
  "version": 1,
  "defaults": { "project": "工作", "estimateMinutes": 30 },
  "tasks": [
    {
      "id": "2026-10-24-1",
      "date": "2026-10-24",
      "title": "写周报",
      "start": "09:30",
      "estimateMinutes": 45,
      "project": "工作",
      "tags": ["专注"],
      "notes": "补充信息"
    }
  ]
}
```

- `date` 和 `title` 必填。
- `id` 应稳定且唯一；同一 ID 再运行会更新原任务。
- `start` 为 `HH:MM`，会转换成具体计划时间。
- `project` / `tags` 支持现有标题或 ID。
- 单次最多 100 项。

## 统计口径

- **按时完成**：计划日为当天，`doneOn` 也在当天。
- **补勾完成**：计划日为当天，后来才勾选完成；仍计入当天计划完成率。
- **未完成**：计划日已过，任务仍未完成。
- **待完成**：计划日为今天，但尚未完成。
- **额外完成**：当天完成，但不在当天计划中。
- 插件首次运行后会保存计划快照；之后改期仍保留旧计划日。

## 数据与导出

复盘数据保存在插件键 `daily-review-data-v1` 中，可通过顶部“导出复盘”导出 JSON，默认保留约两年历史。
