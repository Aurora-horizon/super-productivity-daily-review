# 每日复盘与计划 v2.11.0

## v2.11.0 容量优化

- **任务快照去重**：未来日期不再重复保存任务快照，完成任务只保留必要字段。
- **旧数据自动瘦身**：升级后会自动清理旧快照中的空字段、重复字段和多余副本。
- **容量目标降到约 150 KiB**：比 v2.10.0 的约 220 KiB 更轻，同时在多数情况下仍能保留更多近期任务明细。
- **功能保持不变**：完成率、热力图、趋势、任务详情、勾选同步和新建任务继续使用原有数据口径。

## v2.10.0 修复

- **大归档写入修复**：归档内容改为分块写入，不再把整份 JSON 作为 Windows 命令行参数传入，解决 `spawn ENAMETOOLONG`。
- **归档重试**：最终归档成功后同一周期直接跳过；手动“立即整理并导出”可强制重写并显示真实错误。
- **勾选更流畅**：勾选/取消任务先在界面即时更新，仅调用原生任务 API 同步，不再每次重载全部 700+ 任务和 200+ KiB 复盘数据。
- **插件内新建任务**：顶部新增“＋ 新建任务”，支持标题、日期、项目、预计时长、开始时间和备注；通过官方 `addTask` / `updateTask` 创建并同步到 Super Productivity。

适用于 Super Productivity 19.1.0 的本地插件。它通过官方 Plugin API 读取任务，并把每日计划快照、完成状态和未完成原因保存在插件同步数据中。

## 安装

1. 打开 Super Productivity。
2. 进入“设置 → 插件 / Plugins”。
3. 导入 `daily-review-plugin-v2.11.0.zip`。
4. 启用“每日复盘与计划”。
5. 从顶部按钮、菜单或命令面板打开。

## v2.11.0 界面

- **每日**：动态完成率环形图、具体时间任务时间线、按状态分组的全天任务、任务详情滑入抽屉、筛选器和原因记录。
- **双向勾选**：可在插件中直接勾选或取消任务完成状态，修改会同步回 Super Productivity；时间线、全天任务、其他完成和详情抽屉均支持操作。
- **逾期队列**：今天的页面只汇总逾期的一次性任务；每日、长期、短期和重复任务按各自日期结算。
- **显式任务类型**：在任务详情中直接选择“每日任务 / 一次性任务 / 短期任务 / 长期任务”，短期和长期任务可填写持续天数。
- **类型独立保存**：任务类型使用独立存储键，不会被后台任务快照覆盖，刷新或重新打开后仍会保留。
- **任务系列**：每日、短期、长期任务保存后会按未来 7 天自动补齐，每个日期只生成一次，支持暂停系列。
- **历史类型同步**：设置任务类型后，会按“项目 + 去除日期前缀后的标题”同步到同系列的历史和未来实例。
- **系列日期标题**：每个系列实例会使用自己的计划日期作为标题前缀，例如 `10月29号 晨间阅读`、`10月30号 晨间阅读`、`11月1号 晨间阅读`。
- **日期格式兼容**：识别 `10-28`、`10月28号`、`2026年10月28日`、`【10-28】` 等写法，并统一生成本地中文日期标题。
- **旧副本修复**：升级后会修正之前生成的系列任务标题，使标题日期与任务计划日一致；历史原始任务标题保持不变。
- **逾期仅限一次性任务**：每日、长期、短期和重复任务不会进入逾期延期队列，过期后按当天错过处理。
- **无法完成**：一次性任务可以记录“无法完成”原因，不会计为完成，也不会继续留在逾期队列。
- **原生重复优先**：已使用 Super Productivity 原生重复机制的任务不会重复生成副本。
- **重复任务保护**：自动识别 Super Productivity 重复任务；每日、长期、短期和重复任务过期后会按当天错过处理，不会搬到明天叠加。
- **改期撤销**：每次移至今天或顺延都会记录原日期，顶部“撤销改期”和移动后的提示均可回退。
- **未来任务回退**：未来日期会正确显示全天任务，并可直接“移到今天”。
- **每日收尾**：点击“结束今天”逐项选择顺延、补勾完成或保持未完成；每日任务改为“记为错过”，可记录原因并保存日结时完成率。
- **完成分类**：区分补完历史、提前完成和临时额外完成，避免把不同性质的成果混在一起。
- **原因口径**：今天尚未完成的任务不会再提示“原因待补”，只有已经过去且仍未完成的任务才需要补充原因。

## 任务类型判定

- 优先使用任务详情中的显式类型设置。
- 原生重复任务依据 `repeatCfgId` 自动识别，不会生成插件副本。
- 每日、短期、长期任务保存后自动补齐未来 7 天；滚动打开插件会继续补齐。
- 短期、长期任务按填写天数保存结束日期，超过结束日期后停止生成。
- 每日、短期、长期和重复任务不进入逾期延期队列，过期后自动按当天错过处理。
- 同系列任务通过“项目 + 去除日期前缀的标题”匹配，因此 `10-28 晨间阅读` 与 `10-29 晨间阅读` 会归为同一系列。
- 只有一次性任务可以进入逾期列表并选择移到今天、重新安排、顺延或无法完成。
- “无法完成”会记录原因，不计入完成，并从当前计划中移除；原计划日保留为未完成记录。
- 一次性任务逾期超过 2 天后需要人工重新安排，不再一键滚到明天。
- **归档任务**：受 Super Productivity 官方 Plugin API 限制，已归档任务会显示但勾选框禁用；未归档任务均可双向切换。
- **完成日历**：标准月历。每天显示完成率、状态和任务点；悬停显示摘要，点击带过渡进入当天明细。
- **趋势**：30 天完成率折线图，带绘制动画、悬停数据提示、80% 目标线、近 7 天变化和原因分布。
- **计划导入**：保留手动 JSON 兜底，同时提供 Trae 自动写入指令。
- **实时同步**：在 Super Productivity 或插件内创建、完成、取消完成、修改、删除任务后，双方状态会自动刷新。
- **日期口径**：遵循 Super Productivity 的“一天的开始时间”设置，而不是固定按午夜计算。
- **历史校准**：已删除任务不会继续留在当前/未来统计中；历史中的已删除孤立任务也会清理。

## 自动写入（推荐）

Super Productivity 19.1.0 自带本地 REST API：

- 地址：`http://127.0.0.1:3876`
- 打开方式：设置 → 杂项 → 启用本地 REST API
- 访问令牌：同一设置区域复制
- 只监听本机，不应把端口暴露到公网

配套脚本：`sp-plan.ps1`

```powershell
powershell -ExecutionPolicy Bypass -File "sp-plan.ps1" -PlanFile ".\plan.json"
```

脚本会：

1. 从本机令牌文件或 `SP_REST_TOKEN` 读取令牌。
2. 解析项目与标签。
3. 用任务备注中的 `sp-plan:<id>` 标记识别重复任务。
4. 新建或更新任务，避免重复创建。
5. 输出新建、更新、跳过、失败数量。

## 计划 JSON

```json
{
  "version": 1,
  "defaults": { "project": "工作", "estimateMinutes": 30 },
  "tasks": [
    {
      "id": "2026-10-24-1",
      "date": "2026-10-24",
      "title": "写周报",
      "start": "09:30",
      "estimateMinutes": 45,
      "project": "工作",
      "tags": ["专注"],
      "notes": "补充信息"
    }
  ]
}
```

- `date` 和 `title` 必填。
- `id` 应稳定且唯一；同一 ID 再运行会更新原任务。
- `start` 为 `HH:MM`，会转换成具体计划时间。
- `project` / `tags` 支持现有标题或 ID。
- 单次最多 100 项。

## 统计口径

- **按时完成**：计划日为当天，`doneOn` 也在当天。
- **补勾完成**：计划日为当天，后来才勾选完成；仍计入当天计划完成率。
- **未完成**：计划日已过，任务仍未完成。
- **待完成**：计划日为今天，但尚未完成。
- **额外完成**：当天完成，但不在当天计划中。
- 插件首次运行后会保存计划快照；之后改期仍保留旧计划日。

## 半月文件、自动归档与容量保护（v2.11.0）

- 插件数据单次写入上限为 256 KiB。v2.11.0 会在每次保存前自动检查数据量，并把目标控制在约 150 KiB。
- 默认保留约 16 天的任务明细，使插件内主要保留当前半月；如果数据仍超过目标，会从最旧日期开始继续收缩明细。
- 每个历史日期都会保留一条轻量统计摘要，包括计划数、完成数、完成率、错过数、无法完成数和原因计数。
- 应用目录下自动创建 `daily-review-plugin/archives` 文件夹，并按 `年份/开始日期_结束日期.json` 保存半月归档文件。
- 上半月范围为每月 1 日至 15 日；下半月范围为每月 16 日至月底，不重复记录 15 日。
- 15 日会生成上半月快照，16 日再写入最终版；月底生成下半月快照，次月 1 日再写入最终版。
- 如果当天没有打开插件，下次打开或后台快照运行时会自动补齐归档文件。
- “归档”标签可以查看已生成文件、当前数据大小，并手动执行“立即整理并导出”。
- 把任意半月归档 JSON 拖到“归档”标签的拖放区域，即可离线查看该半月的汇总和任务明细。
- 自动写入应用目录需要启用插件的 Node 文件执行权限；文件只在本地读写，不会上传。

## 数据与导出

复盘数据保存在插件键 `daily-review-data-v1` 中，可通过顶部“导出复盘”导出 JSON。每日统计摘要默认保留约两年；任务明细按容量自动收缩，已结束半月的完整明细保存在应用目录的 `daily-review-plugin/archives` 中。
